The v5 sentence-fed fast-weight memory

One text span does two jobs. The subtask sentence π0.5 already decodes is written, with a one-step delay and a confidence gate, into a Titans-style fast-weight bank; eight learned queries read it back at layer 8 and the retrieved vectors are injected as memory tokens. The bank is therefore a log of "what I have done so far", and the decision sentence wait; target bin is right can only be produced by reading the inspect sentence written a minute earlier.

1. The task the bank has to solve

Each of the 70 labelled episodes (54 train, 8 development, 8 sealed final-test) runs the same five phases. The prompt names an object, the arms open both lids, look inside, close everything and return home, and only then decide which bin to open. At the decision step the lids are closed and the arms are home, so the image contains no evidence about where the banana is. Only the bank does.

Figure 1. The bank is written five times per episode. The only place the side ever appears before the decision is the inspect sentence, written about 20 memory steps (roughly 10 s) before the wait phase begins.

2. Where the memory sits inside π0.5

The base model is unchanged π0.5: SigLIP image tokens plus the prompt go through the Gemma blocks, the subtask sentence is decoded greedily from the causal text span, and the action expert produces a 50-step chunk by flow matching. v5 keeps the v4 dual-bank plumbing at layer 8 of 18 but deletes the task-specific fact head. The semantic bank is fed by the decoded sentence itself; the visual bank still runs but its read is not injected in any stage since A4, so the policy is blind to it.

Figure 2. Read and write are separated in time. The read happens inside the forward pass at layer 8; the write happens after the step, using the sentence decoded one step earlier. Nothing the model writes can influence the same step's decision.

3. Writing: from a sentence to a fast-weight update

A sentence is turned into one key and one value, then committed with the delta rule. Only the output weight of the memory MLP changes, which is what makes the write a single test-time gradient step and lets gaps without writes be collapsed analytically.

Figure 3. The encoder shares the frozen blocks 0 to 8 with the reader, so a sentence lands in the same space the queries live in. Keys and values are unit vectors, which keeps the delta-rule step scale-free.

The write rule at rollout time

Figure 4. The one-step delay (introduced in A4) is what stopped the bank from feeding a sentence back into the very step that produced it. In the oracle stages the label sentence replaces the decoded one and is always confident; the transition contract is identical.

History prefill in training (A5 onward)

Training windows start anywhere in an episode. Before A5 every window began with an empty bank, so a window starting in the wait phase taught the model that closed lids, home arms and an empty bank mean "wait; target bin is X". At a real episode start the bank is empty for the same visual state, and 4 of 8 A4 episodes died at frame 0 with a confident, wrong wait sentence. Since A5 each window starts with the bank prefilled by delta-rule commits of the distinct label sentences before the window (at most 6, with the exact decay gaps between them) and the pending slot holding the delayed sentence. An empty bank now occurs only at frame 0, exactly as in a rollout.

4. Reading: eight queries that depend on the prompt and the last sentence

The read is a forward pass of the fast-weight MLP on eight unit-norm queries. The A6 probe showed why reading had been weak: the queries were identical across frames, images and even instructions (cosine 1.000), because the conditioner's zero-initialised output projection had never opened. A6 gives the queries two explicit inputs and standardizes the instruction rows first.

Figure 5. The instruction term is what lets "find the banana" and "find the grey pepper box" ask the bank different questions. The previous-sentence shift lets the query move with the phase, so the same bank content is read differently while inspecting and while waiting.

5. The training recipe: oracle bank first, own sentences second

Two stages, both with the same architecture and data. Stage A writes the label sentence (oracle bank) so reading and phase tracking are learned on a clean bank. Stage B warm-starts from the A checkpoint and writes the model's own delayed, confidence-gated sentences at half the learning rate, so self-writes only harden what A learned. Direct B from scratch failed: with spurious own "wait" sentences already in the bank, copying its own earlier wait sentence became the easiest way to produce one, and the side was a coin flip.

Figure 6. Cosine schedule, AdamW, gradient clip 1.0, a separate clip of 5.0 on the memory path, no EMA. Sentences are supervised by the label cross-entropy of the causal span; actions by the flow-matching loss; there is no auxiliary memory loss.

6. What each stage showed

Two instruments. The held-out battery replays development windows with the bank in oracle mode and flips the side words inside the stored sentences; if the first decision follows the flipped content the model is reading the bank rather than the image. The self-write rollouts run all eight development episodes end to end on the model's own sentences, which is the only test of phase tracking without a teacher.

The three failures and their fixes

  • Empty bank means "wait". Training windows began with a blank bank anywhere in the episode. Fixed by history prefill (A5).
  • Never reaching "open left bin". The A3/A4 bank stored the wait label side-stripped, so the bank never matched the sentence the model had to produce next. Fixed by writing sentences exactly as labelled (A5). The user chose the exact write over side-stripping to keep the rule general.
  • Queries did not depend on anything. The probe on A4 weights measured cosine 1.000 between queries of different frames, images and prompts. Fixed by standardizing the prompt rows, an identity-initialised instruction term and a zero-initialised previous-sentence shift (A6). B6a then wrote no spurious sentences at all where B5a still had two episodes with early wait writes.

7. Serving loop on the robot

The server holds the bank state between calls. Each replan sends three images, the state and the prompt; the model reads the bank, decodes the subtask sentence with per-token probabilities, samples 50 actions, and returns the sentence, its confidence and the bank contents. The server then applies the same write rule as training on the returned sentence (one-step delay, changed, confidence 0.9) and either commits or decays.

The client is the v4 real-time-chunking client with a v5 readout: it prints the current sentence, marks a committed write with a star, and lists the bank after each commit. Pressing r resets the bank between trials. Compile takes about a minute at warmup; a call then takes about 150 ms on the H100. Today's first robot trials on B6a were reported as working well.

Open items. Checkpoint 1000 of the B6a continuation is serving but has not been through the battery; keep_499 is the judged one. A stability gate (commit only after two or three identical confident steps) is the prepared cure if flickers appear on the robot. The final-test split of 8 episodes stays sealed until a model is declared final.
